# Game Arts master tracker

## Direction

Game Arts is an engine-agnostic art-creation framework that game projects import into their own folder and
use with Claude Code or Codex. Fix the gates that guard approved art, add a storyboard layer so a campaign is
agreed before full-size scene mockups, keep every framework document as one file updated in place (no
versioning), and keep this repository free of engine work and of unrelated or legacy files.

This is the single tracker for this work. [ENHANCEMENT_FIX_PLAN.md](ENHANCEMENT_FIX_PLAN.md) owns the
findings, decisions, acceptance criteria and task lists; this file owns status. The SDLC framework's own
tracker (framework v1.2) is a different tracker and is not changed by this work.

A second workstream was planned on 2026-10-24: make Game Arts better at art for different 2D game styles and genres and friendlier to use. [STYLE_AND_USABILITY_PLAN.md](STYLE_AND_USABILITY_PLAN.md) owns its
findings, decisions (D-8 to D-19), acceptance criteria and task lists (phases P9 to P14); this file owns its status. The first workstream (P0 to P8) is not reopened.

## Completion rules

- A phase is complete only after its acceptance criteria in the plan are met by checks actually run. Record the exact command, exit status, date, environment and tree identity for each.
- Every fix is preceded by a failing test and followed by a revert-the-fix proof; a test that passes on the unfixed code does not count (the standing "guard cannot fail" rule).
- Run focused test selections only (named file or case); never the whole suite locally. CI runs the whole suite.
- Local success does not establish hosted CI, live agent behavior or installed-game migration; those stay `Not run` until observed.
- Status rows describe the stage reached: planned, implemented, locally verified, hosted, accepted.
- Never delete or rewrite a revoked or approved art revision; migrations keep every approved asset valid.
