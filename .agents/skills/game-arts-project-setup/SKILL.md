# Game Arts project setup (in chat)

Policy: master *Project settings and the owner-confirmation gate* (its **setup wizard** bullet), *Art-style profiles*, *World geometry, projection and scale*. Run inside the current Claude Code or Codex chat. The user needs no Python, terminal, JSON or git. Be brief and friendly. **Every setting is the owner's own pick: no setting is ever filled in with a default.** You may say which option you recommend and why; you never choose it for them. Never claim a setting is saved unless the command succeeded and you read it back.

## Start
1. Find the game project (not this framework repository) and read `<game>/.gamearts/project.json` if it exists. For a plain request use it as it stands; for a configuration request summarize it simply and ask what to change.
2. Run `python scripts/gamearts_setup.py status --game-root <game>`. A game with no wizard answers (new, or set up before the wizard existed) gets the whole wizard; the wizard marks each existing value as `(current setting)` and only the owner's pick counts. Do not stop brainstorming or early concept talk while setup is open.
3. If the user names another game folder of theirs, mention its choices as suggestions while you ask; the owner still picks each one.

## The settings page (when the owner is at the computer)
Run `python scripts/gamearts_setup_form.py run --game-root <game>` in the background and wait for it. One page opens in the owner's browser with the same questions, one at a time, choices as cards, an existing game's saved settings marked (never chosen for them), and a summary at the end where they save, or save and confirm. Their click is recorded as their words through the same code as `answer`, and "save and confirm" confirms through the form's own decision, so nothing else is needed. It prints `{outcome, complete, version, answered, unanswered, settings_status}`: exit 0 when they saved (`saved` or `confirmed`), 2 when they left or nobody answered (their answers are kept; carry on with the loop below or ask again). If no browser can open, use the loop. After `saved` (not confirmed), show the summary and confirm as usual.

## The wizard (the loop)
1. `python scripts/gamearts_setup.py next --game-root <game>` returns the next unanswered question: `question.prompt`, the numbered `options` (value, label, description) and a ready `text`. **Show it as given**: use your own choice control (a multiple-choice prompt) where you have one, otherwise print `text` and wait for the number or the words. Add "Something else" only where the options include it.
2. Record the pick: `python scripts/gamearts_setup.py answer --game-root <game> --id <question id> --value <option value> --said "<the owner's own words>" [--text "<detail>"]`. `--said` is what the owner actually said to choose it ("the 32 pixel one"); it is required and never invented, and `show` keeps it beside each pick. A pick that needs a detail (another size as `WIDTHxHEIGHT`, a connected tool's name, a palette description or picture path (a picture path may end ` as NAME` to name the palette; its colours may reach the look's own colour limit, see `docs/PROJECT_SETTINGS.md`), an engine's name, a game name, an angle for isometric) takes `--text`. A refused answer says why; ask again.
3. Repeat until `next` says `complete`. Answering an earlier question again resets only the later questions that depend on it. `python scripts/gamearts_setup.py show --game-root <game>` lists every question, its options and what is answered, plus `possible`: every question that may still appear and what triggers it, so you can tell the owner what is coming (the scale, for one, appears only after the viewpoint).
4. `python scripts/gamearts_setup.py finish --game-root <game>` writes `project.json` from the answers. It refuses while any question is open; nothing is written before that, so a half-answered game has no settings file.

The wizard owns the list of questions and when each appears (`show` prints it as `possible`; `docs/PROJECT_SETTINGS.md` has the table). Which ones apply depends on the world kind (a tile map asks for the viewpoint and tile size, a screen-only game for the screen) and on earlier answers: an image tool that makes the pictures also asks for an optional note (a model or quality level), each fallback tool asks for its own note, and after one is named the wizard asks whether there is another to try after it (up to three, in the owner's order), and a named engine asks for its version. "No note" is a pick like any other and is never assumed; the note itself is the owner's words, passed with `--text`. The look list comes from `presets/styles/` and the engine list from `presets/engines/`. A look with soft edges (or one in the owner's own words) gets one more question, what to do about soft edges, which is saved as a constraint (master *Masking and PNG export policy*). A "top-down" answer is the viewpoint question: the choice between seen from above and a little in front, and straight down, is shown as two options. The isometric tile size and the owner's own angle follow the master's *World geometry, projection and scale*.

Ask only what the wizard asks as a setting. Ask about frame counts, layer names and the like only when an art task needs them, not as settings. Policy constants (the mockup gate, the key colour, one atlas per sheet) are not wizard choices.

## Confirm and save
1. After `finish`, show the owner its `summary` (their picks in plain words and what each one means, for example that "I make the pictures myself" means Game Arts generates none) and its 12-character `version`, and ask for a short confirmation of exactly that. If they defer, wait; the settings stay `inferred`. A scripted or simulated acceptance is not an owner confirmation.
2. On the owner's confirmation run `python scripts/gamearts_asset_lifecycle.py confirm-settings --game-root <game> --by <owner or role> --user-confirmation-ref "<their words>" --presented-version <the version you showed>`. It stamps the real time, refuses settings the wizard did not write, that miss an answer or the owner's words, or whose version is not the one shown, and never takes a typed `confirmed_at`. After a later material change (`art_style`, `world`, `world_kind`, `screen`, `directions`, `animation`, `export`) `finish` sets `needs_review` until the owner reconfirms; existing approved art is flagged for review, never silently revoked. `image_generation` and `engine_target` are not material: an unchanged confirmation stands.
3. Verify: `python scripts/gamearts_asset_lifecycle.py check-settings --game-root <game>` must report valid, owner-confirmed and `setup.complete: true`. It also names the engine profile and the import notes for the chosen look; pass the notes on to the user once. Tell the user in simple terms what was saved and where. If a command failed, say nothing was saved.
4. Mention once that "Add a Game Arts instruction" customizes the pipeline for this game (`game-arts-custom-instructions`).

## Rules
Do the work, not syntax lessons. Never show raw JSON unless asked. Do not re-ask what the saved answers already say unless the owner wants a change. Explain a word from `docs/GLOSSARY.md` in one clause the first time you use it. If your agent has no image tool of its own, do not recommend one: say so when the image generator question comes up and offer "I make the pictures myself" and any connected tool you can see, never picking a paid one for the owner. The mandatory standards (mockup-first approval, exact opaque `#FF00FF`, a measured atlas per sheet, locked masters, honest validation, no ZIP-only delivery) are not choices.
